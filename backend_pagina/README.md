# Contact API

This directory runs the contact API only. It is not the game relay/wallet server and does not serve the website or any directory containing secrets.

Use a supported Node.js LTS release (22 or 24), `npm ci --ignore-scripts`, `npm test`, then `npm start` from this directory. MongoDB must be reachable; startup fails if the connection or collection index fails. No database or third-party service is needed by the tests.

## Configuration

Keep `.env` outside the public website directory and never serve it. Existing `.env` values were not read or changed by this update. Environment variables:

| Variable | Purpose |
| --- | --- |
| `MONGODB_URI` | MongoDB connection string; defaults to local MongoDB. |
| `DATABASE_NAME` | Database; defaults to `base_de_datos_game`. |
| `HOST`, `PORT` | Defaults `127.0.0.1`, `3000`. Bind publicly only through your intended infrastructure. |
| `CONTACT_ALLOWED_ORIGINS` | Comma-separated exact website origins, e.g. `https://your-domain.example`. Defaults allow localhost/127.0.0.1 on ports 3000 and 5500. Include your actual website origin even when proxying the API on the same origin. Wildcards are not accepted. |
| `RECAPTCHA_SECRET` | Private server key for reCAPTCHA v2. If set, Google verification is mandatory. |
| `RECAPTCHA_SITE_KEY` | Matching public reCAPTCHA v2 site key. Setting a secret without this key fails closed with HTTP 503. |
| `RECAPTCHA_HOSTNAMES` | Comma-separated expected Google verification hostnames (no scheme/path). Defaults to hostnames in `CONTACT_ALLOWED_ORIGINS`. Configure domain restrictions in the Google console too. |
| `TRUSTED_PROXIES` | Optional comma-separated trusted proxy IPs/CIDRs (or Express predefined ranges). Defaults to trusting no proxy. Set only when a known reverse proxy overwrites forwarded headers. Do not use a catch-all range. |

Without `RECAPTCHA_SECRET`, the API deliberately uses input validation, origin checks, a honeypot and rate limiting. It does not pretend to verify a CAPTCHA. The previous literal `canvas-captcha-verified` bypass is always rejected.

## Website integration

Route `/api/contact` and `/api/contact/config` from the website's HTTPS origin to this service. The landing page uses these relative URLs. Do not expose this repository or its root as an unrestricted static directory: `.env`, `node_modules`, backend code and internal tools must not be publicly served. Configure TLS and HTTP security headers on your web server, including CSP `frame-ancestors`, `X-Content-Type-Options: nosniff`, and HSTS only on HTTPS domains you control. Meta tags do not implement all these headers.

`GET /api/contact/config` returns only `{ "recaptchaRequired": false, "recaptchaSiteKey": null }`, or the public site key when verification is required. An incomplete CAPTCHA configuration returns 503. It never returns the private secret.

`POST /api/contact` requires `Content-Type: application/json`, no compression, and at most 16 KiB. The body is a JSON object:

| Field | Limit | Required |
| --- | --- | --- |
| `name` | 120 characters | Yes |
| `email` | 254 characters; basic email syntax | Yes |
| `company` | 160 characters | Yes |
| `message` | 5,000 characters | Yes |
| `telegram`, `discord` | 100 characters each | No |
| `website` | Must be empty (honeypot) | No |
| `g-recaptcha-response` | 4,096 characters | When CAPTCHA is configured |

Only strings are accepted; unknown fields are discarded. Successful submission returns `{ "ok": true, "message": "Your message has been received." }`. Errors return `{ "error": "..." }` with HTTP 400, 403, 413, 415, 429 or 503. The rate limit is 5 attempted POSTs per IP per 15 minutes; 429 includes `Retry-After`. The in-memory map has at most 10,000 entries and no timer. For several processes/hosts, implement a shared rate limit at the trusted reverse proxy; local limits alone are per process and reset on restart.

Google verification times out after 5 seconds, validates the returned hostname and rejects redirects, failure responses and client-generated bypass tokens. Contact database operations use a 5-second timeout. Server shutdown waits for HTTP requests before closing MongoDB, with a 10-second forced-close deadline.

## Data compatibility

New submissions are individual documents in `contact_submissions`; they contain the validated fields and `created_at`. This prevents an unbounded `submissions` array from growing past MongoDB's document limit. Existing `contacts` documents and indexes are preserved, and the previous `DROP_EMAIL_INDEX` destructive migration is no longer used. There is no automatic deletion of historical records. Access both collections through your authenticated database administration workflow when you need historical data.

The unauthenticated `GET /api/contacts` data export has been removed (404). The API does not log contact contents, emails, tokens, database connection strings or raw database exceptions and does not persist requester IP addresses. Define a retention policy and authenticated administrative access outside this public API.

## Verification and limits

`npm test` exercises the HTTP API against a mocked database and CAPTCHA provider, including operator objects, oversized requests, spoofed proxy headers, public data exposure, rate-limit memory bounds and CAPTCHA failures. `npm audit` checks the locked dependency graph; zero advisories is not a guarantee that the application has no vulnerabilities. Production TLS/proxy behavior, the real database, real CAPTCHA keys and game smart contracts require their own environment validation.
